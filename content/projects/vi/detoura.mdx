## Lõi tất định

Package luật không phụ thuộc thư viện nào, không dùng đồng hồ và không dùng số ngẫu nhiên. Nhờ vậy, cùng một đoạn code vừa chạy trên trình duyệt để phản hồi tức thì, vừa chạy trên server với vai trò trọng tài. Ván đấu có thể lưu dưới dạng nhật ký nước đi rồi phát lại, và thuật toán tìm kiếm có thể mô phỏng trên chính bộ luật thật.

## Một interface cho mọi game

Luật game cắm vào nền tảng qua một interface có kiểu duy nhất, gồm các bước: khởi tạo ván, áp dụng nước đi, liệt kê nước hợp lệ, báo kết quả, và chiếu trạng thái ra để hiển thị. Server không bao giờ đọc trực tiếp các trường bên trong một ván đấu, nên muốn thêm game mới chỉ cần viết một package luật và một lớp hiển thị.

## Schema vừa là API vừa là test

Schema Zod kiểm tra mọi tin nhắn gửi đến server. Cũng từ những schema đó, hệ thống sinh ra `/openapi.json` và một trang đặc tả trực tiếp cho mười bốn loại tin nhắn WebSocket, phần mà OpenAPI không mô tả được. Ở mỗi lần phát hành, một bộ test chống lệch so sánh tài liệu thiết kế với đặc tả mà dịch vụ đang chạy thực sự trả về.

## Realtime có phòng vệ

Server là bên duy nhất có quyền quyết định trạng thái ván đấu. Mỗi kết nối có giới hạn tần suất theo token bucket và giới hạn kích thước frame, có thể nối lại bằng một token riêng, và mọi sự kiện đều được ghi vào nhật ký kiểm tra. Đồng hồ Fischer do server quản lý và được tách khỏi trạng thái game.

## Giải đấu và triển khai

Giải đấu giữa các bot chạy trên một service riêng, dùng Postgres với câu SQL viết tay. API key chỉ lưu dưới dạng mã băm và được so sánh trong thời gian không đổi, bảng xếp hạng lấy từ một SQL view, còn ván đấu được lưu thành nhật ký hành động có thể phát lại. Hai bot, một dùng minimax với cắt tỉa alpha-beta và một dùng MCTS, được viết để thử tải service. Cả hai service triển khai lên Cloud Run qua GitHub Actions mà không lưu khoá. Mỗi bản phát hành phải qua test hợp đồng, test Playwright và smoke test WebSocket chạy trên bản triển khai thật.

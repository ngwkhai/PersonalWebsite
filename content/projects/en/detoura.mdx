## The rule that makes it a game

A 9×9 board and two pawns racing to opposite edges is a footrace, not a game. What makes Detoura a game is the wall: ten of them per player, and placing one is an alternative to moving.

The constraint is what matters. **A wall may never leave a player with no route at all to their goal.** You can lengthen someone's path, force them around, cost them four turns — you cannot lock them out. Every wall placement therefore requires a reachability check for both players before it is legal, which is the one piece of real algorithmic work in the rules and the piece that decides whether the game is fair.

## How it is being built

The project follows a gated workflow: eleven stages from idea to a verified live URL, and a stage does not open until the previous gate passes. Planning artefacts live in `flow/`, build work is cut into cards, and each card is one session with its own scope and its own done-evidence.

The point of the discipline is that "done" means something checkable. **C-001 is done because the deployed URL passed a ten-minute WebSocket smoke test** — not because the code compiles locally.

## Where it stands

Scaffold, CI/CD and the realtime transport are live on Cloud Run. The engine — movement, jumping over an adjacent pawn, the win condition — and the interface are the next two cards, deliberately built in parallel against a mocked interface so neither blocks the other.

Stack is a TypeScript monorepo, deployed to Cloud Run, with the interface tokens measured from a reference design in the browser rather than eyeballed.

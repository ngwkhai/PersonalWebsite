## Course material as a build artifact

Slide decks and reference documents are generated with `python-pptx` and `python-docx`, and figures are rendered from real datasets. Exercises are compiled into the JSON that the platform reads. A fix made at the source reaches every artifact, and nothing is written twice.

## Verification by execution

The release gate runs the material instead of reading it. Reference solutions must pass, starter files must fail in the expected way, and generated files must match the committed ones byte for byte. Structural checks run in the same pass, and any failure blocks the release.

## The platform

The platform uses Next.js 16 on the App Router, with server components and actions calling the data layer directly. Learners sign in with Google against an invitation list and receive a verified session cookie. Every read and write happens on the server, files are served from a private bucket as time-limited signed URLs, database rules deny access by default, and all access is written to an audit log.

## Running learners' code

Exercises follow the coding-interview pattern: the learner writes one function, and a harness adds the tests when it runs. CPU-sized work runs in the browser through Pyodide. GPU work goes to a queue that leases an account from a pool, dispatches the job, and collects logs and outputs into object storage. It then returns the account with its quota accounted for. No request waits on a long-running job, and a simulation mode makes the whole path testable on a laptop.

## Two applications

The public site is a static export, and the platform is a separate server-backed app. Changes to the marketing pages never redeploy the system that holds learner data.
